# Internationalization & Localization Guide (i18n)

Rustwarden is designed from the ground up to be multi-language while keeping all source code, identifiers, comments, and technical documentation in **English**.

---

## 1. Currently Supported Languages

| Code | Language (English) | Native Name | Locale File |
| :--- | :--- | :--- | :--- |
| `en` | English (Default & Fallback) | English | `src/i18n/locales/en.json` |
| `es` | Spanish | Español | `src/i18n/locales/es.json` |
| `ca` | Catalan | Català | `src/i18n/locales/ca.json` |

---

## 2. Architecture

1. **Frontend UI (`src/i18n/config.ts`)**:
   - Powered by `i18next` and `react-i18next`.
   - Every React component retrieves strings via `const { t } = useTranslation()`.
   - Zero user-facing strings are hardcoded in JSX/TSX components.
2. **Backend Error Localization (`src-tauri/src/error.rs`)**:
   - Rust errors (`AppError`) serialize into `{ errorKey, message }`, where `errorKey` maps directly to `errors.*` in the JSON locale files (e.g. `errors.invalidCredentials`, `errors.twoFactorRequired`, `errors.networkError`).
3. **Native System Tray Synchronization (`src-tauri/src/tray.rs`)**:
   - Whenever the user changes the language in the Login screen or Settings modal, `useSettingsStore` invokes the `sync_tray_locale` Tauri command with the translated `tray.*` strings so the native OS context menu updates immediately without restarting the application.

## 3. How to Add a New Language

Adding a new translation requires **only two steps**:

### Step 1: Create the JSON dictionary
Copy the reference English file to a new file named after the ISO 639-1 language code:

```bash
cp src/i18n/locales/en.json src/i18n/locales/fr.json
```

Translate all string values in `src/i18n/locales/fr.json`. Keep all JSON keys and `{{variable}}` interpolation placeholders unchanged.

### Step 2: Register the language in `src/i18n/config.ts`
Import your new JSON file at the top of `src/i18n/config.ts` and add an entry to `SUPPORTED_LOCALES`:

```ts
import fr from "./locales/fr.json";

export const SUPPORTED_LOCALES: readonly LocaleMetadata[] = [
  // ... existing locales (en, es, ca)
  {
    code: "fr",
    name: "French",
    nativeName: "Français",
    translation: fr,
  },
] as const;
```

### Step 3: Verify Key Parity
Run the automated verification check via Make or npm:

```bash
make test-i18n
```

This script verifies that every locale file in `src/i18n/locales/` has the exact same nested key structure as `en.json`.
